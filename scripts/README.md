# scripts: deploy and data

- `ship.sh`: the one deploy command. It checks `web/.env.production.local`, builds the app, deploys the database rules, creates or updates the trip (copying `data/trip.example.json` to `local/trip.json` when that is missing), seeds the parties, stamps the invite title into the link preview, deploys the site, and prints the two links. Each step prints its name; the first failure stops the script and names the step. A second run is safe.
- `create-trip.mjs`: creates or updates the trip from `local/trip.json` and prints the crew link and the organizer link. `--emulator` writes to the emulator. The trip id and the organizer key stay in `local/trip.state.json`, and the emulator's in `local/trip.state.emulator.json`, so the live trip never reuses an id or key a test run printed; delete the file for a new trip. The file's optional `admins` lists the organizers' emails (plan, D15); each run replaces the admin list with it. Each starting date option is written by its own path, so options friends added with "Add dates" stay. It writes only the areas and venues of `data/places.json` whose destination the trip file lists. To add a destination (Koh Samui, 25 Nov 2026), add it to `data/places.json` and to `local/trip.json`'s `destinations` (`"kohSamui": { "name": "Koh Samui" }`, as in `data/trip.example.json`), run `create-trip.mjs`, then `seed-parties.mjs`; the seed stops on a lineup place the trip file lacks.
- `stamp-preview.mjs`: writes the organizer's invite title (`info/inviteTitle`, set in the "Invite" sheet; the default is "Indonesia/Thailand Trip 2027") into the link preview: og:title and `<title>` of `public/index.html`, og:title of the built `public/app/index.html`. Run it after the build and before the hosting deploy: `node scripts/stamp-preview.mjs`. When the read fails it warns, keeps the current title and exits 0, so it never stops a deploy. `--emulator` reads the emulator.
- `stamp-event-previews.mjs`: writes one page file per shared events address (`public/trip/<tripId>/events/…`, git-ignored), so a link preview shows the event's name, date, place and picture and not the invitation. `ship.sh` runs it after `stamp-preview.mjs`. It reads the live trip, never fails the deploy, and an event added after a deploy gets its own preview at the next one.
- `backfill-activity.mjs`: seeds the Activity list of a trip made before it, once, from data that already has a time: each member's "joined", each stay, each event a friend added, each link, and the confirmed dates. A second run rewrites the same lines and adds none. `--emulator` uses the emulator's trip; `--trip <id>` names a trip.
- `backfill-show-photos.mjs`: gives the trip's events their own picture. It runs the events check here with the link reader's code, and sets `parties/shows/<id>/photoUrl` from each found event's picture, on the show with the same id, only where the show has none. It prints what it would write; `--write` writes. `--emulator` uses the emulator (`FIREBASE_DATABASE_EMULATOR_HOST`, else 127.0.0.1:9000); `--trip <id>` names a trip.
- `trip-file.mjs`: `validateTripFile`, the one check of a trip file.

Run every script from the repo root. `local/` is git-ignored: the trip file, its id, its key and the links never reach the public repo.
